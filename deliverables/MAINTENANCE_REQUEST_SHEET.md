- 링크: https://docs.google.com/spreadsheets/d/1i8gbKgnTgBiMXSaEFXrTn7u7iv9YxA8q6G3DqJRubu4/edit
- 프로젝트 계정 `general@zezari.com`에 편집 권한을 부여했다.

## 구성

### 유지보수 요청서

테스터가 요청 한 건을 한 행에 기록하는 기본 작업표다. 요청번호, 테스트 환경,
화면과 URL, 캡처 링크, 현재 상황, 재현 절차, 기대 결과, 요구사항, 심각도,
우선순위, 처리 상태, 개발 답변, 완료일과 재테스트 결과를 관리한다.

요청 구분, 심각도, 우선순위, 처리 상태와 재테스트 결과는 드롭다운으로 제공한다.
상태와 심각도는 조건부 색상으로 표시되며, 상단 네 행은 스크롤 중에도 고정된다.

### 작성안내

캡처 방법, 재현 절차와 요구사항 작성법, 환경 정보, 재테스트 방법을 설명한다.
전화번호, 주소, 이메일, 얼굴은 필요한 범위만 남기고 마스킹해야 하며 비밀번호,
인증번호와 API 키는 기록하지 않는다.

### 코드목록

요청 구분, 심각도, 처리 상태와 재테스트 결과의 의미 및 사용 기준을 정리한다.

## 운영 흐름

1. 테스터가 문제 화면을 캡처하고 열람 가능한 링크를 만든다.
2. `유지보수 요청서`에 현재 상황, 재현 절차, 기대 결과와 요구사항을 등록한다.
3. 개발 담당자가 처리 상태와 조치내역을 갱신한다.
4. 수정완료 후 테스터가 같은 절차로 재테스트하고 통과 또는 실패를 기록한다.
5. 통과한 요청은 완료 처리하고, 실패한 요청은 추가 현상을 같은 행에 누적한다.

## 갱신 기준

- 화면, 메뉴 또는 운영 절차가 변경되면 선택값과 작성안내를 함께 갱신한다.
- 테스터에게 전달할 때는 개별 Google 계정에 편집 권한을 부여한다.
- 링크가 있는 모든 사용자가 편집하도록 공개하지 않는다.
- 문서 구조를 변경하면 개발 및 발표 로그에 변경 이유와 적용일을 기록한다.
