- 위치공유 공개 API 요청 제한
- HTTPS 강제용 HSTS, MIME 스니핑 방지, 프레임 제한, 권한 정책
- 환경변수 파일과 `reference/` Git 제외

## 3. 이번 개선 조치

### 파일과 미디어

- 이미지 업로드를 JPEG, PNG, WebP, GIF로 제한했다.
- 파일 확장자나 브라우저 MIME만 믿지 않고 실제 파일 시그니처를 검증한다.
- 저장형 SVG 등 실행 가능한 이미지 형식이 동일 출처에서 표시되는 경로를 차단했다.
- 보호자 음성 데이터 URL의 허용 오디오 형식과 최대 디코딩 용량을 제한했다.
- 대상자 수정 시 브라우저 hidden 필드의 기존 사진·음성을 신뢰하지 않고 DB의 현재 값만 유지한다.

### 인증과 권한

- 신규 비밀번호 PBKDF2 반복 횟수를 310,000회로 높였다.
- 기존 120,000회 해시는 계속 로그인할 수 있도록 호환성을 유지했다.
- 저장 해시의 반복 횟수·salt·digest 형식을 검증해 비정상 연산량 유도를 차단했다.
- 운영 환경 인증번호 토큰은 `NEXTAUTH_SECRET`이 없으면 발급되지 않도록 했다.
- 이메일·SMS 인증 완료 토큰 소비를 조건부 UPDATE로 변경해 동시 재사용을 차단했다.
- DB 관리자 권한도 활성 보호자 계정일 때만 인정한다.
- 운영 세션 쿠키에 secure-cookie 동작을 명시했다.

### API와 외부 연결

- 이메일·SMS 인증번호 발송에 요청자 기준 5분·1시간 제한을 추가했다.
- 공개 보호자 알림 요청과 지도 검색 API에 요청 제한을 추가했다.
- Web Push 구독 주소는 HTTPS, 표준 포트, 허용 푸시 공급자 도메인, 암호화 키 형식을 검증한다.
- 알림 URL은 안전한 내부 경로 또는 자격정보가 없는 HTTPS URL만 저장하고 표시한다.
- 위치공유, 가입 인증, 알림함, 푸시 구독 응답에 `no-store`를 적용했다.

### 관리자와 브라우저

- 관리자 작업 후 이동 경로를 `/admin` 내부로 제한해 외부 오픈 리다이렉트를 차단했다.
- 관리자 CSV 내보내기에서 `=`, `+`, `-`, `@` 등으로 시작하는 값을 중립화해 스프레드시트 수식 실행을 방지했다.
- 전역 헤더에 제한적 CSP, DNS prefetch 차단, cross-domain policy 차단, Origin-Agent-Cluster를 추가했다.
- 이미지 응답에는 별도 sandbox CSP와 `nosniff`를 적용했다.

## 5. 잔여 위험과 다음 운영 조치

- 현재 CSP는 Toss, Kakao, Meta 등 기존 외부 연동을 깨지 않도록 `object-src`, `base-uri`, `frame-ancestors` 중심으로 적용했다. 향후 외부 도메인 목록을 확정한 뒤 nonce 기반 전체 CSP로 강화한다.
- DB 기반 요청 제한은 서버리스 인스턴스 간에도 동작하지만 공격 대응 정책은 Vercel Firewall의 속도 제한과 함께 운영하는 것이 좋다.
- 이미지 시그니처 검증은 실행형 파일 차단 목적이다. 향후 업로드 용량이 커지면 별도 Blob 저장소와 악성 파일 검사 서비스를 검토한다.
- 결제 완료는 Toss 서버 승인으로 검증되지만 장기적으로 브라우저 복귀 실패까지 처리하려면 결제 웹훅과 대사 작업을 추가하는 것이 좋다.
- 로그인, 결제, 위치공유, 관리자 권한 경계를 대상으로 정기적인 자동 통합 테스트와 제3자 침투 테스트를 권장한다.
- 하드코딩된 초기 관리자 이메일을 운영할 경우 해당 Google 계정의 다중 인증과 복구 수단을 반드시 유지한다.
