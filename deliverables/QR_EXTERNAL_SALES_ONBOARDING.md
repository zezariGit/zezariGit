# 미배정 QR 기반 외부 판매 가입·매칭

## 1. 목적

외부 판매 플랫폼에서 구매한 미배정 QR 상품을 스캔한 사용자가 ZEZARI 회원으로 가입하고, 첫 관리대상을 등록할 때 방금 스캔한 물리 QR을 정확히 연결한다.

## 2. 사용자 흐름

1. 사용자가 미배정 QR의 `/find/{publicKey}` 주소에 접근한다.
2. 화면에 일반 `회원가입`, 기존 회원 로그인, Google·카카오·네이버·Facebook 가입 버튼을 표시한다.
3. 가입 또는 로그인 버튼을 누르면 서버가 해당 QR을 2시간 예약하고 HTTP 전용 쿠키를 발급한다.
4. 일반 가입과 SNS 최초 가입 모두 기존 Solapi 휴대폰 인증을 거친다.
5. 보호자 필수 정보를 완료하면 관리대상 신규 등록 화면으로 이동한다.
6. 첫 관리대상 저장 시 예약 토큰과 QR 공개키가 모두 일치하는 미배정 QR만 조건부로 연결한다.
7. 연결 성공 후 예약값과 브라우저 쿠키를 제거하고 QR 연결 완료 화면을 표시한다.

기존 회원이 QR 화면에서 로그인한 경우에도 신규 관리대상 한 명을 등록하면 동일한 정확 매칭 절차를 적용한다.

## 3. 일반 가입과의 차이

| 구분 | QR 선택 규칙 | 대상자 등록 |
| --- | --- | --- |
| 일반 회원가입·일반 대상자 추가 | 예약되지 않은 미배정 QR 중 생성일이 가장 빠른 QR | 첫 대상자 최소 1명 필수 |
| 미배정 QR 스캔 후 가입·로그인 | 스캔 후 2시간 예약한 정확한 QR | 신규 대상자 저장 시 예약 QR 필수 매칭 |

일반 자동 배정 쿼리는 유효한 가입 예약이 걸린 QR을 제외한다. 따라서 외부 판매 상품의 QR을 다른 가입자가 먼저 가져가지 않는다.

## 4. 데이터와 API

### DB 스키마 버전 39

`qr_codes`에 다음 서버 전용 컬럼을 추가했다.

- `signup_claim_hash`: 원문 예약 토큰의 SHA-256 해시
- `signup_claim_expires_at`: 예약 만료 시각
- `signup_claim_started_at`: 예약 시작 시각

원문 예약 토큰은 DB에 저장하지 않는다.

### API

- `POST /api/qr-claim/start`
- 입력: `publicKey`
- 성공: 유효한 미배정 QR을 2시간 예약하고 `zezari_qr_signup_claim` HTTP 전용 쿠키 발급
- 실패: 비활성·폐기·기배정·다른 가입 절차에서 예약 중인 QR은 409 오류
- 남용 방지: 요청자 식별 해시에 대해 10분당 10회 서버 제한을 적용하며 원문 IP는 저장하지 않는다.

## 5. 경쟁 상태와 실패 처리

- 정확 매칭은 `public_key`, `subject_id IS NULL`, 활성 상태, 예약 해시, 만료 시각을 한 번의 조건부 `UPDATE`로 확인한다.
- 연결 조건이 바뀌면 임의의 다른 QR로 대체하지 않고 신규 대상자 INSERT를 보상 삭제한 뒤 재스캔 오류를 표시한다.
- 일반 배정도 조건부 UPDATE 후 대상자 연결 결과를 다시 확인하고, 경쟁에서 밀리면 다음 미배정 QR을 재시도한다.
- 같은 브라우저가 다른 미배정 QR로 가입을 다시 시작하면 이전 예약을 해제한다.

## 6. 가입 완료 규칙

- 신규 일반 회원과 신규 SNS 회원은 보호자 정보 완료 후 대상자 등록 화면으로 이동한다.
- 관리자가 아닌 보호자 계정에 대상자가 0명이면 대시보드로 우회하지 못하고 대상자 신규 등록 화면으로 이동한다.
- SNS 가입은 별도 비밀번호를 받지 않으며 휴대폰 인증과 보호자 필수 정보는 동일하게 적용한다.

- `npm run build`: 통과

- `npm run test:qr-claim`: 예약 QR 정확 매칭 및 일반 배정의 예약 QR 제외 통과
- `git diff --check`: 통과
- 운영 Turso 스키마 버전 39와 예약 컬럼 3개 생성 확인
- 데스크톱 및 375px 모바일에서 일반·SNS·기존 회원 버튼, 동일 폭, 가로 넘침 없음 확인

## 8. 운영 주의사항

- 2시간이 지난 가입 흐름은 정확 QR 연결을 보장할 수 없으므로 사용자가 물리 QR을 다시 스캔해야 한다.
- 예약 토큰이나 DB 해시는 사용자 화면, 로그, 발표자료에 노출하지 않는다.
- 외부 판매 채널의 상품 설명에는 반드시 상품 수령 후 QR 스캔부터 가입하라는 순서를 안내한다.
