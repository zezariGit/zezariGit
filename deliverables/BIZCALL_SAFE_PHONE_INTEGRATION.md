# 비즈콜 050 안심번호 연동 산출물

작성일: 2026-07-24
대상 서비스: REAL_QR_FIND / `https://zezari.vercel.app`

## 0. 2026-08-01 운영방식 전환

이 문서의 보호자별 영구 자동 발급 방식은 과거 구현 기록으로 보존한다. 현재 운영 소스는 사전 확보한 050 번호를 24시간 공유·재사용하는 풀 방식으로 전환되었으며, 신규 구현과 운영 절차는 `deliverables/BIZCALL_SAFE_PHONE_POOL.md`를 기준으로 한다. 기존 `guardians.safe_phone*` 컬럼은 호환용으로만 남고 QR 공개 페이지의 신규 번호 원본으로 사용하지 않는다.

## 1. 목적

보호자가 입력한 실제 휴대폰 번호를 QR 공개 페이지에 노출하지 않고, 비즈콜이 발급한 050 안심번호를 통해서만 보호자에게 전화가 연결되도록 한다.

## 2. 참고 규격

- `reference/Bizcall 서비스 [안심번호] HTTPS 연동규격서_v_1_29(2024).pdf`
- 연동 방식: HTTPS `POST`
- 요청 인코딩: UTF-8
- 본문 형식: `application/x-www-form-urlencoded`
- 응답 형식: JSON
- 인증값: `iid + 대상 번호`를 MD5 처리한 바이트를 Base64 인코딩

## 3. 구현 범위

### 3.1 신규 050 번호 자동 발급

- API: `/link/auto_mapp.do`
- 입력: Interface ID, 보호자 실제 전화번호, 보호자 식별 메모, 인증값
- 결과: 계정에 할당된 미사용 050 번호를 반환받아 보호자에게 연결

### 3.2 기존 050 번호 재연결

- API: `/link/set_vn.do`
- 사용 시점: 보호자의 연락받을 전화번호가 변경되거나 관리자가 재연결을 요청한 경우
- 입력: 기존 050 번호, 새 실제 전화번호, 통화 연결 여부 `Y`, 인증값

### 3.3 자동 연동 시점

1. 일반 회원가입 완료
2. SNS 최초 회원가입 정보입력 완료
3. 보호자 정보에서 연락받을 전화번호 저장
4. 관리자 보호자 상세 화면의 `안심번호 발급/재연결` 실행

## 4. DB 변경

`guardians` 테이블에 다음 컬럼을 추가했다.

| 컬럼 | 의미 |
| --- | --- |
| `safe_phone` | 발급된 050 안심번호 |
| `safe_phone_status` | `pending`, `provisioning`, `active`, `failed` |
| `safe_phone_provider` | 발급 사업자, 현재 `bizcall` |
| `safe_phone_synced_at` | 마지막 정상 연결 일시 |
| `safe_phone_last_error` | 최근 발급/연결 실패 사유 |

DB 스키마 버전은 `20`이다.

## 5. 개인정보 보호 규칙

- `guardians.phone`은 로그인한 보호자와 관리자 업무 화면에서만 사용한다.
- QR 공개 페이지 쿼리는 `safe_phone_status = 'active'`인 경우에만 `safe_phone`을 반환한다.
- 비즈콜 설정 누락, 장애, 발급 실패, 재연결 실패 시 실제 전화번호로 대체하지 않는다.
- 발급되지 않은 공개 페이지에는 `안심번호 준비중`만 표시한다.
- 활성 050 번호는 `tel:` 링크로 제공해 휴대폰에서 바로 전화할 수 있다.
- API 오류에는 전화번호와 인증값을 기록하지 않는다.

## 6. 환경변수

다음 값은 서버 전용이며 브라우저 코드로 전달하지 않는다.

```dotenv
BIZCALL_ENABLED=true
BIZCALL_API_BASE_URL=
BIZCALL_INTERFACE_ID=
BIZCALL_TIMEOUT_MS=8000
```

- `BIZCALL_API_BASE_URL`: 델피콤/비즈콜에서 계약 계정에 안내한 HTTPS 연동 서버 주소
- `BIZCALL_INTERFACE_ID`: 델피콤에서 발행한 20자 이하 Interface ID
- `BIZCALL_TIMEOUT_MS`: API 최대 대기 시간, 기본 8초

규격서에는 `/link/...` 상대 경로만 있으므로 API 기본 URL을 임의로 추정하면 안 된다.

## 7. 운영 절차

1. 비즈콜 계약 계정에서 050 회선을 할당한다.
2. 비즈콜 담당자로부터 API 기본 URL과 Interface ID를 확인한다.
3. 로컬 `.env.local`과 Vercel Production 환경변수에 등록한다.
4. 관리자 `보호자 관리 > 기본정보 > 안심번호 발급/재연결`을 실행한다.
5. 보호자 실제 전화에서 050 번호로 시험 통화한다.
6. QR 공개 페이지에 원 전화번호가 없는지 확인한다.

## 8. 장애 처리

- 신규 발급 실패: 상태를 `failed`로 기록하고 공개 페이지에는 번호를 표시하지 않는다.
- 설정 누락: 상태를 `pending`으로 기록한다.
- 보호자 번호 변경 후 재연결 실패: 기존 050 번호를 공개하지 않는다.
- 관리자 재시도: 같은 보호자의 기존 050 번호가 있으면 새 번호를 추가 발급하지 않고 재매핑한다.

## 9. 검증 항목

- `npm run build`
- `git diff --check`
- 스키마 버전과 신규 컬럼 생성 확인
- 환경변수 미설정 상태에서 프로필 저장이 실패하지 않는지 확인
- 공개 쿼리가 비활성 안심번호를 반환하지 않는지 확인
- 실제 비즈콜 환경변수 등록 후 신규 발급 및 번호 변경 재매핑 시험
- 050 번호 통화 연결 및 QR 공개 페이지 `tel:` 링크 확인

## 10. 남은 외부 설정

소스 구현은 완료했지만 실제 050 발급 시험에는 비즈콜 계약 계정의 API 기본 URL, Interface ID, 사용 가능한 할당 회선이 필요하다. 해당 값은 소스와 문서에 기록하지 않고 Vercel 환경변수로만 관리한다.

## 11. 2026-07-31 계정 및 운영환경 확인

- 첨부 규격서 20페이지를 확인했으며, 보호자 전화번호를 직접 변환하는 방식이 아니라 비즈콜이 할당한 050 가상번호에 실제 착신번호를 매핑하는 방식임을 재확인했다.
- 신규 매핑은 `/link/auto_mapp.do`, 전화번호 변경과 해지는 `/link/set_vn.do`를 사용한다.
- 로그인된 비즈콜 서비스 현황에서 전체 가상번호 100개, 할당 가상번호 5개가 확인되어 미할당 회선을 사용할 수 있는 계정 상태다.
- `050번호 관리` 화면에서 가상번호와 착신번호 매핑 관리 기능이 활성화되어 있음을 확인했다.
- 로컬 `.env.local`과 Vercel 환경변수에는 `BIZCALL_API_BASE_URL`, `BIZCALL_INTERFACE_ID`가 아직 등록되어 있지 않다.
- 따라서 계약과 회선은 준비되어 있지만, API 기본 URL과 Interface ID를 비즈콜에서 확인해 서버 환경변수에 등록하기 전에는 REAL_QR_FIND의 자동 발급 호출이 실행되지 않는다.
- 실제 전화번호, 계정 비밀번호, API 인증값은 산출물과 로그에 기록하지 않았다.
