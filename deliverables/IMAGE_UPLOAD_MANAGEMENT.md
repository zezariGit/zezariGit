# REAL_QR_FIND 이미지 업로드 관리

## 구현 범위

- 기존 관리대상 사진의 서버 제한은 1MB였다.
- 기존 소스에는 보호자 사진 업로드 기능이 없었다.
- 보호자정보에 보호자 사진 업로드와 미리보기를 추가했다.
- 관리자 메뉴 `이미지업로드 관리`에서 보호자 사진과 관리대상 사진 제한을 각각 설정한다.
- 기본값은 두 항목 모두 1MB이며 운영 안정성을 위해 1~4MB 정수 범위에서 설정한다.

## 관리자 사용 순서

1. 관리자 페이지 왼쪽 메뉴에서 `이미지업로드 관리`를 연다.
2. 보호자 사진과 관리대상 사진의 제한 용량을 MB 단위로 입력한다.
3. `용량 제한 저장`을 누른다.
4. 저장된 값은 사용자 파일 선택 안내와 서버 저장 검증에 즉시 적용된다.

## 사용자 동작

- 허용 형식은 JPEG, PNG, WebP, GIF다.
- 선택한 이미지가 관리자 제한보다 크면 브라우저 알림으로 허용 용량을 안내하고 파일 선택을 해제한다.
- 브라우저 검사를 우회한 요청도 서버에서 같은 DB 설정값으로 다시 차단한다.
- 보호자 사진은 본인 인증 세션에서만 `/api/guardians/me/photo`로 조회한다.
- 관리대상 사진은 기존과 같이 소유 보호자 또는 관리자 권한을 확인한 뒤 제공한다.

## DB 및 서버

- DB 스키마 버전: 41
- `image_upload_settings`
  - `guardian_photo_max_bytes`
  - `subject_photo_max_bytes`
  - `updated_at`
- `guardians`
  - `photo_data_url`
  - `photo_name`
- Next.js Server Action 본문 제한은 8MB다. 관리대상 음성 데이터와 기타 입력을 함께 전송하는 경우를 고려해 사진 한 파일 설정 상한을 4MB로 제한했다.

## 함께 반영한 UI 개선

- 내정보 팝업은 URL 서버 이동 대신 클라이언트 상태로 즉시 열리며, 대시보드에서 이용권 정보를 미리 조회한다.
- 대시보드의 QR 이미지는 광고·수정·등록완료 등 실제 필요한 대상에 대해서만 생성한다.
- 알림과 내정보 팝업은 바깥 영역 클릭 또는 터치와 `Esc` 키로 닫힌다.
- 모바일 실종광고 팝업은 콘텐츠 높이 기준 grid 행과 고정 높이 닫기 버튼을 사용한다.

## 검증 기준

- 기본 제한값이 보호자·관리대상 각각 1,048,576바이트인지 확인한다.
- 관리자 저장 후 두 사용자 업로더의 안내와 서버 오류 메시지가 같은 MB 값인지 확인한다.
- 제한 초과 파일 선택 시 알림이 나타나고 파일 입력값이 비워지는지 확인한다.
- 모바일에서 광고 팝업 닫기 버튼이 세로로 늘어나지 않는지 확인한다.
- 알림과 내정보 팝업 내부 조작은 유지되고 바깥 영역 터치만 닫힘으로 처리되는지 확인한다.
