# 위치정보 이용·제공사실 및 열람·고지 취급대장

## 구현 범위

- 위치공유가 발생하면 `location_use_ledger`에 이용·제공사실 확인 자료를 자동 기록한다.
- 보호자 푸시 발송 결과까지 성공 또는 저장 전용 상태로 추가 기록한다.
- 위치정보주체의 열람·고지 요청은 `location_disclosure_ledger`에 별도 기록한다.
- 두 원장은 위치정보 권한이 있는 관리자만 조회할 수 있고, 내보내기 권한이 있는 관리자만 CSV로 내려받을 수 있다.
- 원장에는 실제 위도·경도 원문을 넣지 않으며 식별값, 처리 사실과 결과만 보존한다.
- 각 원장은 이전 레코드 해시와 현재 레코드 해시를 연결하여 변경 여부를 확인할 수 있다.

## 이용·제공사실 확인 자료

| 양식 항목 | 저장 필드 |
| --- | --- |
| 대상 | `data_subject_ref` |
| 취득경로 | `acquisition_route` 또는 `method` |
| 제공 서비스 | `service_name` |
| 제공받는 자 | `recipient` |
| 이용일시 | `created_at` |

## 열람·고지 사실 취급대장

| 양식 항목 | 저장 필드 |
| --- | --- |
| 취급자 | `handler_ref`, `handler_guardian_id` |
| 요청자 | `requester_ref` |
| 목적 | `purpose` |
| 일시 | `created_at` |

관리자는 `관리자 > 위치정보 보안`에서 열람·고지 요청을 기록한다. 요청자 입력란에는 불필요한 개인정보 대신 내부 접수번호 또는 업무상 필요한 최소 식별값을 사용한다.

## 운영 절차

1. 발견자가 QR 공개 페이지에서 위치공유에 동의한다.
2. 서버가 좌표를 암호화 저장하고 이용·제공사실 원장에 수집 사실을 자동 기록한다.
3. 보호자 푸시 또는 알림함 제공 결과를 원장에 추가 기록한다.
4. 위치정보주체가 열람·고지를 요청하면 권한 있는 취급자가 요청자 식별값과 목적을 입력한다.
5. 서버가 취급자와 처리일시를 자동 확정하고 열람·고지 취급대장에 기록한다.
6. 월간 점검 또는 제출 증빙이 필요하면 권한 있는 관리책임자가 CSV를 내려받는다.

## 보안 원칙

- 실제 좌표는 이용·제공사실 및 열람·고지 원장에 저장하지 않는다.
- 원장 행의 수정·삭제 UI는 제공하지 않는다.
- 원장 조회와 내보내기 자체도 `location_access_logs`에 기록한다.
- 법정 보존기간과 최종 양식은 제출 전에 위치정보 관련 전문기관 또는 법률 전문가의 검토를 거친다.
