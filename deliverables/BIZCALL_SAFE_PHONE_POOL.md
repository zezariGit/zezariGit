# 비즈콜 통화 시점 안심번호 자동 배정 산출물

작성일: 2026-08-08
대상 서비스: REAL_QR_FIND / `https://zezari.family`

## 1. 목적

관리대상 QR 공개 페이지를 조회하는 것만으로는 050 번호를 점유하지 않는다. 발견자가 실제로 보호자에게 전화하려고 `안심번호로 보호자에게 전화하기`를 누른 순간에만 비즈콜이 사용 가능한 번호를 자동 선택하고 보호자 연락처에 임시 연결한다.

애플리케이션에는 100개 번호를 미리 등록하거나 고정 재고 수를 두지 않는다. 비즈콜 계약에 번호가 추가되면 공급자 자동 배정 대상에 즉시 포함되므로 100개를 초과하는 확장에도 소스 변경이 필요 없다. 동시에 연결 가능한 최대 수는 비즈콜 계정에 실제로 준비된 미매칭 번호 수다.

## 2. 사용자 흐름

1. 공개 QR 페이지는 QR 활성, 대상자 매칭, 서비스 이용 가능 여부만 확인한다.
2. 페이지 조회만으로 비즈콜 API를 호출하지 않는다.
3. 발견자가 통화 버튼을 누르면 `POST /api/find/{public_key}/safe-phone`을 호출한다.
4. 서버가 동일 보호자의 유효한 임시 연결을 확인하고, 없을 때 비즈콜 자동 배정 API를 호출한다.
5. 비즈콜이 빈 번호를 선택해 보호자의 비공개 전화번호에 연결한다.
6. 서버는 컬러링과 보호자 수신 전 알림멘트를 적용하고 1시간 자동 해제를 다시 확정한다.
7. 브라우저에는 050 번호와 `tel:` 주소만 반환하고 전화 앱을 연다.
8. 실제 보호자 원전화번호는 HTML, API 응답, 로그, 관리자 CSV에 노출하지 않는다.

## 3. 비즈콜 API

| 순서 | 경로 | 역할 |
| --- | --- | --- |
| 1 | `/link/auto_expire_mapp.do` | 비어 있는 050 번호를 공급자가 원자적으로 선택하고 1시간 자동 해제 예약 |
| 2 | `/link/set_vn.do` | 계약 컬러링과 알림멘트 적용 및 통화 연결 활성화 |
| 3 | `/link/auto_expire_update.do` | 옵션 변경 뒤에도 자동 해제 시간이 유지되도록 만료시간 재확정 |
| 운영 | `/link/set_vn.do` | 관리자 긴급 해제 또는 배정 실패 보상 해제 |

비즈콜이 번호를 선택하므로 애플리케이션에서 무작위 번호를 가져와 경쟁적으로 선점하지 않는다. 규격이 선택 순서를 보장하지는 않지만, 공급자 측 원자적 자동 배정으로 동시 요청 중복을 막는다.

인증값은 `iid + 대상값`의 MD5 32자리 문자열을 Base64 인코딩해 만든다. Interface ID, 컬러링 ID, 알림멘트 ID와 보호자 원전화번호는 서버 환경변수 또는 서버 DB에서만 사용한다.

## 4. 데이터 구조

### `safe_phone_pool`

사전 재고 테이블이 아니라 공급자가 실제 반환한 번호의 현재 상태와 운영 이력을 저장한다. `allocation_source='provider_auto'`가 신규 자동 배정을 뜻한다.

### `safe_phone_call_requests`

통화 버튼 요청을 저장한다. QR, 보호자, 관리대상, 비식별 요청자 해시, 반환 안심번호, 성공·실패 상태, 재사용 여부, 만료시각을 기록한다. IP 원문은 저장하지 않는다.

### `safe_phone_assignment_history`

번호별 배정·해제·만료 이력을 저장한다. 신규 통화 배정 출처는 `finder_call`이다.

### `safe_phone_assignment_locks`

보호자 단위 30초 잠금으로 동시에 여러 번 버튼을 눌러도 복수 번호가 배정되지 않게 한다.

## 5. 제한과 장애 처리

- 동일 요청자와 QR은 10분에 5회, 동일 요청자는 1시간에 20회로 제한한다.
- 같은 보호자에게 유효한 1시간 연결이 있으면 같은 번호를 재사용한다.
- 비즈콜 결과 코드 6은 번호 부족으로 변환해 잠시 후 재시도 안내를 반환한다.
- 배정 후 컬러링·알림멘트 또는 DB 기록이 실패하면 공급자 연결을 즉시 보상 해제한다.
- 원전화번호로 직접 연결하는 fallback은 두지 않는다.

## 6. 관리자 화면

`안심번호 관리`는 번호 사전 추가·삭제·수동 매칭 화면이 아니다. 다음을 제공한다.

- 공급자 자동 배정으로 관측된 번호 수
- 현재 통화 연결중, 자동 해제, 처리중·오류 상태
- 보호자·대상자, 배정일시, 최근 접근, 자동 해제시각, 공급자 동기화시각
- 번호별 발견자 통화 요청 및 해제 이력
- 장애 시 현재 연결 긴급 해제
- CSV 다운로드

## 7. 환경변수

```dotenv
BIZCALL_ENABLED=true
BIZCALL_API_BASE_URL=https://api.050bizcall.co.kr
BIZCALL_INTERFACE_ID=
BIZCALL_COLORING_ID=
BIZCALL_ANNOUNCEMENT_ID=
BIZCALL_ON_DEMAND_LEASE_HOURS=1
BIZCALL_TIMEOUT_MS=8000
```

실제 값은 `.env.local`과 Vercel 암호화 환경변수에만 저장하고 문서, Git, 로그에는 기록하지 않는다.

## 8. 검증 결과

- Next.js 전체 빌드 성공 및 신규 API 라우트 생성 확인
- 운영 Turso 스키마 버전 35, 자동 배정 출처 컬럼, 통화 요청 테이블 확인
- 활성 QR 공개 페이지 HTTP 200 및 통화 버튼 표시 확인
- 페이지 조회만으로 통화 요청 이력이 생성되지 않음을 확인
- 실제 비즈콜 자동 배정, 컬러링·알림멘트 적용, 1시간 자동 해제 갱신 성공
- 시험 번호는 실제 전화 발신 없이 즉시 비즈콜과 DB에서 해제
- 보호자 원전화번호가 공개 응답에 포함되지 않음
- Vercel 운영 배포 후 `zezari.family`, `zezari.vercel.app`, 공개 QR 페이지와 통화 배정 API 정상 응답 확인
