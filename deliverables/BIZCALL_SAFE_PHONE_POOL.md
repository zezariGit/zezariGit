# 비즈콜 안심번호 공유 풀 운영 산출물

작성일: 2026-08-01
대상 서비스: REAL_QR_FIND / `https://zezari.family`

## 1. 목적

보호자마다 050 번호를 영구 발급하지 않고, 사전에 확보한 10~20개의 비즈콜 안심번호를 공유 풀로 운영한다. 유효한 관리대상 QR 공개 페이지가 열릴 때 보호자 원전화번호와 사용 가능한 050 번호를 24시간 연결하고, 만료 후 다른 보호자에게 재사용한다.

보호자의 원전화번호는 공개 페이지, 브라우저 응답, 로그에 노출하지 않는다. 풀 배정이나 비즈콜 연동이 실패하면 원전화번호로 대체하지 않고 `안심번호 준비중`만 표시한다.

## 2. 배정 정책

1. QR이 활성 상태이고 관리대상과 매칭되어 있으며 서비스 이용권이 유효할 때만 배정을 시도한다.
2. 해당 보호자에게 아직 유효한 배정이 있으면 같은 050 번호를 재사용하고 마지막 접근일시만 갱신한다.
3. 유효한 배정이 없으면 `사용 가능` 번호를 오래 등록된 순서로 선택한다.
4. 사용 가능한 번호가 없으면 현재 배정 중인 번호 가운데 매칭일시가 가장 오래된 번호를 회수해 새 보호자에게 연결한다.
5. 비즈콜 `/link/auto_expire_update.do`에 선택한 050 번호, 보호자 원전화번호, `expire_hour=24`를 전달한다.
6. 서버 DB에도 같은 만료일시를 저장한다. 비즈콜 자동 만료와 서버 임대 만료를 함께 사용한다.
7. 관리자 수동 매칭도 동일한 24시간 정책을 사용한다.
8. 같은 보호자의 동시 QR 접근은 보호자 단위 잠금으로 직렬화하고, 같은 050 번호의 동시 배정은 행 버전 조건으로 차단한다.

## 3. 비즈콜 API

| 작업 | 경로 | 주요 값 |
| --- | --- | --- |
| 24시간 연결/교체 | `/link/auto_expire_update.do` | `iid`, `vn`, `rn`, `expire_hour=24`, `memo`, `memo2`, `auth` |
| 관리자 수동 해제 | `/link/set_vn.do` | `iid`, `vn`, `rn`, `crn=N`, `memo`, `auth` |

참고 규격은 `reference/Bizcall 서비스 [안심번호] HTTPS 연동규격서_v_1_29(2024).pdf`이다. 인증값과 원전화번호는 서버 전용으로 처리한다.

## 4. 데이터 구조

### `safe_phone_pool`

| 컬럼 | 의미 |
| --- | --- |
| `safe_phone` | 관리자가 등록한 사전 확보 050 번호, 중복 불가 |
| `status` | `available`, `assigning`, `assigned`, `releasing`, `failed`, `disabled` |
| `guardian_id`, `subject_id` | 현재 연결된 보호자와 접근을 발생시킨 관리대상 |
| `assigned_at`, `expires_at` | 현재 매칭 시작일시와 24시간 만료일시 |
| `last_accessed_at` | 같은 보호자가 마지막으로 QR에 접근한 일시 |
| `provider_synced_at` | 비즈콜 API가 정상 처리된 최근 일시 |
| `last_error` | 최근 연동 오류. 인증값이나 원전화번호는 저장하지 않음 |
| `admin_memo` | 번호 구분용 관리자 메모 |
| `version` | 번호 중복 선점을 막는 낙관적 잠금 버전 |

### `safe_phone_assignment_history`

번호별 보호자·관리대상, 배정·만료·해제일시, 회수 사유, 배정 출처를 누적한다. 회수 사유는 24시간 만료, 가장 오래된 매칭 회수, 관리자 수동 해제, 보호자 연락처 변경, 번호 삭제로 구분한다.

### `safe_phone_assignment_locks`

보호자별 30초 임시 잠금을 저장한다. 동시에 여러 QR 요청이 도착해도 한 보호자에게 복수 번호가 배정되지 않게 하며 정상 처리 후 즉시 삭제한다.

기존 `guardians.safe_phone*` 컬럼은 과거 데이터 호환을 위해 남지만 신규 공개 페이지 배정의 원본으로 사용하지 않는다.

## 5. 관리자 화면

왼쪽 메뉴의 `안심번호 관리`에서 다음 작업을 수행한다.

- 전체, 사용 가능, 매칭 중, 확인 필요 현황 조회
- 050 번호와 관리자 메모 추가
- 번호, 보호자, 관리대상 검색 및 상태 필터
- 번호별 현재 보호자, 관리대상, 매칭일시, 만료일시, 최근 접근일시, API 동기화일시 확인
- 보호자 이름·연락처·이메일 조회 후 선택 번호에 24시간 수동 매칭
- 현재 매칭 수동 해제
- 사용 가능한 번호 삭제
- 번호별 배정·회수 이력 확인
- CSV 다운로드

매칭 중인 번호를 삭제하면 비즈콜 해제를 먼저 수행한 뒤 풀에서 삭제한다. API 설정이 없거나 해제에 실패하면 삭제하지 않는다.

## 6. 환경변수와 운영 준비

```dotenv
BIZCALL_ENABLED=true
BIZCALL_API_BASE_URL=
BIZCALL_INTERFACE_ID=
BIZCALL_TIMEOUT_MS=8000
```

- 규격서는 상대 경로만 제공하므로 `BIZCALL_API_BASE_URL`을 추측하지 않는다.
- 비즈콜에서 발급한 실제 연동 서버 주소와 Interface ID를 확인해 로컬 및 Vercel 서버 환경변수에 등록한다.
- 환경변수가 없으면 관리자 화면에 설정 필요 상태를 표시하며 실제 매칭 API는 실행하지 않는다.
- 확보한 050 번호는 관리자 화면에서 한 번씩 추가한다. 실제 번호는 소스와 문서에 기록하지 않는다.

## 7. 장애 및 개인정보 처리

- 비즈콜 연결 실패 번호는 `failed`로 표시하고 오류를 관리자 상세에 남긴다.
- 실패 번호는 즉시 공개하지 않으며 원전화번호도 공개하지 않는다.
- 보호자 연락처 변경 시 현재 풀 매칭과 과거 호환 매칭을 해제하고 다음 QR 접근에서 새 번호로 다시 연결한다.
- 24시간이 지난 DB 배정은 다음 조회 시 자동 회수한다. 비즈콜 측 연결도 `expire_hour=24`로 자동 만료된다.
- 모든 번호가 사용 중이면 가장 오래된 배정을 교체하므로, 해당 보호자가 다시 QR 접근하면 현재 사용 가능한 번호를 새로 배정받는다.

## 8. 검증 기준

- `npm run build` 성공
- `git diff --check` 성공
- 같은 보호자 동시 요청에서 한 번호만 반환
- 서로 다른 보호자가 같은 번호를 동시에 선점하지 못함
- 기존 유효 배정 재사용
- 빈 번호 우선 배정, 모두 사용 중이면 가장 오래된 배정 회수
- 24시간 만료 후 `available` 복귀 및 이력 종료
- 관리자 추가, 검색, 수동 매칭, 해제, 삭제, CSV 다운로드
- 환경변수 미설정 시 원전화번호 비노출과 명확한 설정 안내
- 실제 비즈콜 설정 후 시험 번호 1건으로 연결, 통화, 수동 해제, 24시간 자동 만료 확인

## 9. 현재 외부 의존사항

소스와 DB/UI 구현은 완료되었다. 실제 통화 연결 시험은 비즈콜 API 기본 URL과 Interface ID를 서버 환경변수에 등록하고, 관리자 화면에 계약 계정의 050 번호를 추가한 뒤 수행해야 한다.

## 10. 2026-08-01 운영 검증

- Vercel 운영 관리자 `안심번호 관리` 화면에서 스키마 버전 31의 신규 테이블 생성과 빈 풀 조회를 확인했다.
- 왼쪽 메뉴, 현황 카드, 번호 추가 폼, 검색·상태 필터, CSV 버튼, 그리드, 오른쪽 상세 빈 상태가 정상 렌더링됐다.
- 서버 설정 경고에 `BIZCALL_API_BASE_URL`, `BIZCALL_INTERFACE_ID` 누락이 표시됨을 확인했다.
- 실제 활성 QR 공개 페이지를 열어 `안심번호 준비중`이 표시되고 보호자 이름, 원전화번호, 이메일, 주소가 렌더링되지 않음을 확인했다.
- 관리자 화면과 공개 QR 화면의 브라우저 콘솔 오류는 없었다.
- 계약 번호가 아직 풀에 등록되지 않아 실제 번호 연결, 통화, 자동 만료 시험은 수행하지 않았다.
