# 관리자 결제패스

## 1. 목적

- 관리자 계정이 상품, 구독, 광고의 결제 이후 기능을 실제 Toss 승인 없이 실행할 수 있게 한다.
- 화면만 완료 페이지로 이동시키지 않고 기존 결제 완료 처리와 동일한 주문·구독·광고 상태 변경을 수행한다.
- 테스트 거래가 실제 매출로 집계되지 않도록 별도로 표시한다.

## 2. 적용 화면

- 상품 단독구매 결제: `/shop` 주문정보 단계
- 상품과 함께 구매하는 구독 결제: `/shop` 주문정보 단계
- 온라인 실종광고 결제: `/ads/checkout/[id]`

일반 사용자는 기존 결제 버튼만 볼 수 있다. 관리자 휴대폰번호 목록 또는 `guardians.is_admin = 1`에 해당하는 로그인 사용자에게만 `결제패스` 버튼을 표시한다.

## 3. 처리 흐름

1. 관리자가 주문·배송지·대상자·쿠폰 또는 광고 정보를 입력한다.
2. 결제 화면에서 `결제패스`를 누른다.
3. Toss 결제는 발생하지 않지만, 광고 패스는 실제 Meta 광고비가 발생한다는 안내를 확인한다.
4. 기존 결제 준비 API에 `adminPass: true`를 전달한다.
5. 서버가 세션의 관리자 권한을 다시 확인한다.
6. 상품·구독·광고별 기존 결제 완료 DB 함수를 실행한다.
7. 거래의 결제수단을 `관리자 결제패스`로 저장하고 테스트 결제 플래그를 설정한다.
8. 해당 결제 완료 페이지로 이동한다.

## 4. 보안 규칙

- 버튼 노출 여부와 별개로 모든 준비 API가 서버에서 관리자 권한을 검증한다.
- 로그인하지 않은 요청은 HTTP 401, 일반 회원의 패스 요청은 HTTP 403으로 거절한다.
- 브라우저에서 `adminPass` 값을 임의로 보내도 관리자 권한이 없으면 완료 처리되지 않는다.
- Toss Payments 승인 API와 실제 카드 승인은 호출하지 않는다.
- 광고 결제패스는 서버 관리자 권한 확인 후 일반 광고 결제와 같은 Meta 자동 발행 함수를 호출한다.

## 5. 데이터 처리

- `product_orders.is_test_payment`
  - 일반 Toss/쿠폰 결제: `0`
  - 관리자 결제패스: `1`
- `subject_ads.is_test_payment`
  - 일반 Toss 결제: `0`
  - 관리자 결제패스: `1`
- 테스트 결제 식별키는 `admin-pass-product-*`, `admin-pass-subscription-*`, `admin-pass-ad-*` 형식을 사용한다.
- 관리자 주문·결제 목록에는 테스트 거래가 표시되며 결제수단으로 구분할 수 있다.
- 대시보드와 결제관리의 매출 합계 및 매출 추이에서는 `is_test_payment = 1` 거래를 제외한다.

## 6. 상태 변경

- 상품 단독구매
  - 주문을 `paid`로 변경한다.
  - 배송상태를 `preparing`으로 변경한다.
- 구독 포함 상품
  - 주문을 `paid_waiting_activation` 또는 `activated`로 변경한다.
  - QR 활성화 전이면 구독을 `ready`로 저장한다.
  - 이미 활성 QR과 유효 구독이 있으면 기존 완료 로직에 따라 기간을 연장한다.
- 광고
  - 결제완료 시각과 테스트 결제정보를 저장한다.
  - `meta_publish_queued`로 저장한 뒤 일반 결제와 같은 Meta 자동 발행 경로를 실행한다.
  - 저장된 지역 또는 전국 범위, 거리, 기간과 `meta_budget_amount`를 실제 Meta 광고 세트에 적용한다.
  - Meta 시작 시각은 결제 처리 약 1분 후로 예약하며, Meta 검토가 지연되면 실제 게재도 늦어질 수 있다.

## 7. 운영 주의사항

- 결제패스도 실제 주문·구독·광고 상태를 변경하므로 운영 DB에서 테스트할 대상자를 신중히 선택한다.
- 광고 결제패스는 Toss 과금만 생략하며 실제 Meta 광고 생성과 예산 집행은 생략하지 않는다.
- 테스트 상품 주문은 배송관리 목록에 나타날 수 있다.
- 테스트 결과가 필요 없어진 경우 관리자 화면에서 해당 주문·광고 상태를 정리한다.

## 8. 스키마

- DB 스키마 버전: `22`
- 신규 컬럼:
  - `product_orders.is_test_payment`
  - `subject_ads.is_test_payment`
