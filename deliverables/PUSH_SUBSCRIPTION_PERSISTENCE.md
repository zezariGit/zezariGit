# 푸시 알림 연결 유지 및 자동 복구

## 확인된 원인

- 제자리 로그인 세션의 운영 만료 기간은 90일이다. 하루나 이틀 뒤 알림이 끊기는 현상은 로그인 만료가 직접 원인이 아니다.
- 푸시 주소는 브라우저·운영체제의 정책에 따라 갱신되거나 폐기될 수 있다.
- 기존 구현은 폐기된 주소를 전송 실패 시 서버에서 삭제했지만, 사용자가 `설정` 팝업을 다시 열 때만 현재 주소를 서버에 저장했다. 따라서 팝업을 다시 열기 전에는 알림 대상 기기가 없는 상태가 계속될 수 있었다.
- 푸시 발송 자체는 로그인 화면이나 활성 세션이 열려 있지 않아도 서버에 저장된 유효한 기기 주소로 전달된다.

## 반영한 자동 복구

- 앱의 모든 화면에서 푸시 연결 상태를 관리하는 전역 동기화 컴포넌트를 실행한다.
- 알림 권한이 유지된 기기는 다음 시점에 현재 구독 주소를 서버에 다시 저장한다.
  - 앱 실행 및 페이지 로드
  - 백그라운드에서 화면으로 복귀
  - 인터넷 연결 복귀
  - 서비스 워커 교체
  - 푸시 연결 직후
  - 앱이 열려 있는 동안 6시간 간격
- 브라우저가 지원하는 경우 서비스 워커의 `pushsubscriptionchange` 이벤트에서 새 주소를 즉시 저장한다.
- 서비스 워커 단계의 저장이 실패하면 열려 있는 앱 화면에 재동기화를 요청한다.
- `/sw.js`는 항상 최신 파일을 확인하도록 캐시 금지 헤더를 적용한다.
- 개인화 화면과 API 응답을 서비스 워커 캐시에서 제외하고 앱 아이콘·매니페스트만 캐시한다.
- 브라우저가 만료일을 제공하지 않은 구독은 `0`이 아닌 `null`로 보존한다.

## 로그인과의 관계

- 이미 서버에 저장된 정상 푸시 주소로 알림을 보내는 과정에는 로그인 세션이 필요하지 않다.
- 새 주소를 특정 보호자 계정에 다시 연결하는 과정에는 계정 식별이 필요하므로 로그인 상태에서 자동 저장한다.
- 현재 90일 세션 유지 로직과 함께 동작하며, 로그인 상태에서 앱을 다시 열면 별도 버튼 조작 없이 복구한다.

## 기기에서 확인할 사항

- iPhone·iPad는 홈 화면에 설치한 제자리 앱에서만 웹 푸시를 받을 수 있다.
- 사용자가 운영체제 또는 브라우저 설정에서 알림 권한을 끄거나, 설치 앱·브라우저 데이터를 삭제하면 웹 서비스가 권한을 강제로 되돌릴 수 없다.
- 방해 금지·집중 모드와 제조사 절전 정책은 알림 표시 시점을 제한할 수 있다.
- 위 조건을 제외하고 알림 권한과 로그인 정보가 유지되면 앱 재실행 시 연결을 자동 복구한다.

## 회귀검사

`npm run test:push`는 전역 복구 마운트, 재연결 이벤트, 서비스 워커 구독 변경 처리, 개인화 캐시 제외, 서비스 워커 캐시 금지 헤더와 DB 만료일 정규화를 검사한다.
